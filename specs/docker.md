# Docker

## Image (`Dockerfile`)

Production image (`stopan:latest`) based on `ruby:4.0.7-slim`, built in two stages:

- gems installed with `BUNDLE_DEPLOYMENT=1`, without the development group
- assets precompiled at build time with a dummy secret
- runs as the non-root user `rails` (uid 1000)
- `bin/docker-entrypoint` runs `bin/rails db:prepare` (create, migrate) and
  `bin/rails db:seed` (admin user if missing, see auth.md) before starting
  the server
- Thruster on port 80 in front of Puma (port 3000)
- `HEALTHCHECK` calls `/up`
- `/rails/storage` holds the SQLite databases and uploaded files; mount a
  volume there

## Local run (`compose.yaml`)

One service, `web`, published on `${PORT:-3000}`, with a named volume
`storage`. Configuration comes from `.env` (template: `.env.example`), which
`make docker-up` creates with generated secrets when missing
(`bin/setup-env`).
Targets: `make docker-up`, `docker-down`, `docker-logs`, `docker-build`,
`docker-check`.

## Development in Docker (`compose.dev.yaml`, `Dockerfile.dev`)

For working on the code without installing Ruby on the host, and without a
rebuild or restart per change.

- `Dockerfile.dev`: `ruby:4.0.7-slim` with build tools and SQLite, no
  application code, user `rails` (uid 1000), `RAILS_ENV=development`.
- The source tree is bind-mounted at `/rails`, so code, views, CSS and
  locales apply on the next page load (Rails reloading, Propshaft).
- Gems (`/usr/local/bundle`), the development database (`/rails/storage`)
  and `/rails/tmp` are named volumes of the compose project `stopan-dev`,
  apart from the host's `vendor/bundle`, `storage/` and `tmp/` used by
  `make run`. `BUNDLE_APP_CONFIG` keeps bundler away from the host's
  `.bundle/config`.
- `BUNDLE_FROZEN=true`: the container never rewrites the mounted
  `Gemfile.lock` (its bundler would add a checksum line). After a Gemfile
  change run `make deps` on the host, then `make docker-dev-restart`.
- On start: `bundle install` when needed, `bin/rails db:prepare` (creates,
  migrates and seeds the admin from `ADMIN_*` in `.env`), Puma on port 3000
  published only on `127.0.0.1:${DEV_PORT:-3000}`.
- Targets: `make docker-dev` (start or update, idempotent),
  `docker-dev-restart` (after Gemfile or `config/` changes),
  `docker-dev-logs`, `docker-dev-down` (volumes kept).

Verified 2026-10-26: first start about 30 s (gems installed), `/up` 200,
admin seeded, runs as uid 1000, CSS served; a view edit showed on the next
request without a restart and the working tree stayed clean.

## Build context (`.dockerignore`)

The image gets only what the app runs: no `.env*`, git data, agent or
editor folders (`.hermes`, `.claude`), git hooks, `specs/`, `todo/`,
`session/`, `docs/`, `test/`, `deploy/`, the development files
(`Dockerfile.dev`, `compose.dev.yaml`) or host gems (`vendor/bundle`).

## Smoke test (`make docker-check`)

Builds the image, then `bin/docker-check` runs it with throwaway secrets
(generated, never printed, `.env` is not read) and a throwaway volume on
`127.0.0.1:${PORT:-3190}` and fails unless:

- none of the excluded files above is in `/rails` and the image does not
  run as root;
- `/up` answers 200 within 60 seconds;
- the sign-in page has the Stopan title and its fingerprinted stylesheet
  is served;
- the seeded admin signs in (303) and `/admin` answers 200;
- after `docker restart` `/up` answers again and the database still holds
  exactly the one seeded user (seeding is idempotent, data is in the
  volume).

The container and volume are removed afterwards, also on failure.

## Environment variables

| variable | required | purpose |
|----------|----------|---------|
| SECRET_KEY_BASE | yes | signs sessions and cookies; generated by `bin/setup-env`, or `bin/rails secret` |
| RAILS_FORCE_SSL | no, default true | redirect to HTTPS, HSTS, secure cookies (compose sets false for localhost) |
| RAILS_ASSUME_SSL | no, default true | trust that a proxy terminates TLS (compose sets false for localhost) |
| APP_HOST | no | host for links in emails |
| MAILER_SENDER | no | From address of all emails |
| SMTP_ADDRESS, SMTP_PORT, SMTP_USERNAME, SMTP_PASSWORD, SMTP_AUTHENTICATION, SMTP_TLS, SMTP_DOMAIN | no | outgoing email; without SMTP_ADDRESS nothing is sent (notifications.md) |
| ADMIN_EMAIL, ADMIN_PASSWORD, ADMIN_USERNAME | no | admin user created when missing; generated by `bin/setup-env` |
| REGISTRATION_OPEN | no, default false in production | `true` lets anyone sign up (auth.md) |
| RAILS_LOG_LEVEL | no, default info | log level |

## Verified

2026-10-26: `stopan:latest` built (Docker 29, arm64, `ruby:4.0.7-slim`;
about 150 MB compressed, 600 MB unpacked) and `make docker-check` passed;
the healthcheck reported `healthy`, the security headers (CSP,
`nosniff`, `X-Frame-Options`, `httponly` session cookie) were present.
Production deployment is designed separately in specs/deploy.md.

## Security Note

`.env` is ignored by git and by the Docker build context; keep it that way.
Behind a public address, terminate TLS in a proxy and keep both SSL
variables at their default `true`. The development container runs with
reloading and detailed errors; it publishes only on 127.0.0.1 and must not
be exposed beyond the workstation.
